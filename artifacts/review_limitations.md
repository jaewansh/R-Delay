# 문서 검토의 실제 범위 — v0.1

## 실제 수행
- GitHub 문서 실행환경에서 Python, Pandoc, LibreOffice Writer/Math, PyMuPDF를 사용해 Word 및 PDF 파일을 생성했다. 상세 버전과 원본 커밋은 environment_check.json을 참조한다.
- Word 신청서의 네이티브 OMML 수식 3개, 개인정보 공란, 요약·지원동기 글자 수, 키워드 수를 구조적으로 검사했다.
- 신청서 변환 PDF 5쪽과 종합설계 PDF 21쪽의 전 페이지를 PNG로 렌더링했다. 페이지 경계를 벗어난 텍스트와 대체문자 검사를 수행했다.
- 처음에는 Word 수식 객체가 있어도 PDF에서 수식 글자가 추출되지 않는 문제를 확인했다. LibreOffice Math를 포함한 환경에서 4가지 네이티브 삽입 방식을 시험하고, 실제 수식 문자(β, γ, ∑)가 출력되는 전체 문단 방식으로 재생성했다.
- 재생성된 신청서 PDF 3쪽의 추출 텍스트에서 미분·분수·합을 포함한 SIS, 결합행렬, R_d 식이 출력된 것을 확인했다. 원본 식은 사용자 지시와 대조했다.
- 생성 원본의 문안과 핵심 페이지 추출 텍스트를 읽어, 수리모델을 후속 연구로 이동하지 않은 점과 미구현·미실행 구분을 확인했다.

## 수행하지 못한 검사
- 생성된 전체 페이지 이미지를 이 대화에서 직접 열어 확인하는 육안 검수는 완료하지 못했다. 공개 raw PDF/이미지 열기는 Cache miss를 반환했고 로컬 container/Python은 초기화 오류였다.
- 따라서 자동 텍스트·경계·수식 문자 검사를 한글의 모든 자형, 수식의 모든 괄호·첨자, 미세한 겹침·표 배치까지 육안 확인한 것으로 표현하지 않는다.
- Microsoft Word 앱 자체에서의 렌더링은 검사하지 않았다. 페이지 수 5쪽은 LibreOffice 변환 결과다. 사용자 글꼴·편집환경에서 내용 변경 후 다시 확인해야 한다.
- /home/oai/skills/docx/SKILL.md 및 pdfs/SKILL.md는 로컬 실행이 시작되지 않아 읽지 못했고 원격 runner에는 존재하지 않았다. 읽었다고 주장하지 않는다.
- 모델 수치시험, 웹/API 실행·배포, 실제 고객·운송자료·정확도·비용 절감은 이번 문서 bootstrap에서 검사하지 않았다.

## 파일 성격
생성된 Word와 PDF는 요청한 v0.1 1차 제출·설계 문서다. 실제 파일 생성 성공과 렌더링 성공은 확인했지만, 전체 기능이 구현되거나 최종 제출 전 육안 검수가 끝난 문서는 아니다. 개인정보·서명·증명서·비밀키는 넣지 않았다. 공식 동의·서약 원문을 임의로 대체하지 않았다.
