# 구현 상태 — 문서 v0.1 / 서비스 v0.2

## 보존한 문서
참가신청서 Word·종합설계 PDF v0.1과 당시 문서 생성·자동검사 기록은 그대로 보존한다. 전체 문서 육안검수는 미완료다. 이번 서비스 작업으로 기존 PDF를 재검수한 것처럼 표시하지 않는다.

## 실제 서비스 소스
- `engine/sis.py`: 원안 SIS, 다른 집단 크기 변환, 입자별 R_d.
- `engine/filtering.py`: 로그-OU 전이, 베타-이항/음이항 우도, 가중치·ESS·재표본추출.
- `engine/queueing.py`: 선석 전진방정식 uniformization, 흡수 넘침, 대상선박 시간, 육상 처리.
- `engine/calibration.py`: 관측에서 상수 회복률 하나 추정, 합성 이후 구간 비교.
- `engine/simulation.py`: 위 모듈의 실제 호출, 원래 마감·비용·실행조건 판단.
- `api/`: 입력 검사, 실제 계산 요청, 불변 실행 조회·관측수정·JSON 저장.
- `web/`: 실제 API 응답으로 그래프·관측·대기·배차를 표시하는 반응형 웹.
- `tests/`, `scripts/check_runtime_browser.py`: 수리·API·실제 Chromium 검사 원본.

## 실행 여부의 판단 기준
소스가 존재하는 것과 검사를 실행해 통과한 것은 다르다. 실행 워크플로가 성공했을 때만 아래 파일이 생성된다.
- `artifacts/runtime/validation_summary.json`: Python 버전·소스커밋·실제 pytest 결과.
- `artifacts/runtime/browser_check.json`: 실제 API/Chromium의 입력·갱신·오류·JSON·모바일 검사.
- `image/runtime/`: 실제 실행 화면과 녹화. 가상의 목업이 아님.
- `deliverables/RDelay_runtime_v0.2.zip`: 해당 실행의 소스와 증거 패키지.

이 파일이 없거나 실패가 기록되어 있으면 검증 완료로 표시하지 않는다. PNG 생성·자동 E2E 성공과 사람이 전체 페이지를 직접 보는 육안검수는 별개다.

## 제한 / 아직 미구현·미실행
실제 항만·고객 자료와 정확도·절감 효과 검증, 외생변수 ML, 일반 다시간 스트리밍과 늦은 관측 재처리, 임의 대기열 관측 공동 갱신, 다화물 공동 최적화, 공개 인터넷 배포·인증·영속저장. Docker 파일은 제공하지만 실제 컨테이너 실행 여부는 검증 요약에 별도 기록한다.

현재 서비스는 2거점·합성자료·10:00 관측1회와 알려진 초기 선박 수에 한정된다. 새로운 선석 시나리오B의 원래마감은16:00이며 과거13:15예제 숫자를 강제하지 않는다. 상세 계약은 docs/runtime_contract.md.

이 제한을 표시하는 것은 해당 모듈을 대회 이후 연구로 미룬다는 뜻이 아니다. 구현한 범위와 남은 개발을 구분한다. 개인정보·증명서·서명·비밀키를 추가하지 않았다. main 자동병합·기본브랜치 변경·타 저장소 수정·공개전환·유료결제·외부배포는 하지 않는다.
